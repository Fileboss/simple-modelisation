# mcd-svg

Vocabulary: [GLOSSARY](../../../GLOSSARY.md) (MCD, Entity, Association, Leg, Cardinality, CIF, Inheritance, Note, Notation, Legend). Shared code lives in the model package ([ADR 0004](../../adr/0004-shared-model-package.md)).

## Problem Statement

A developer wants to illustrate the README of each of their repos with its architecture and the MCD of its database, generated by an agent over MCP and committed as images GitHub displays. System design diagrams already come out as plain SVG (`export_diagram`, the app's exports, the all-diagrams zip), but MCDs do not: `export_diagram` answers "MCDs are not drawn yet", the zip leaves them out, and the app's MCD export is a capture of the page, whose SVG wraps HTML that design tools and some viewers do not render.

## Solution

An MCD is drawn as plain SVG shapes (rects, paths, text), framed on its content, on white, looking like the canvas, in either Notation:

- **Merise** (Looping's style): Entities with their orange header, Identifier underlined; Associations as cyan rounded boxes; Legs with their Cardinalities placed as on the canvas (R for a relative Leg); CIFs as circles with their dashed lines and arrow; Inheritances as triangles with their constraint; Notes; the boxes' drop shadow.
- **UML**: classes listing `name : Type` with their flags; a binary Association's name on its line between its classes, its Attributes in an association class joined by a dashed line; an N-ary Association as a diamond, its CIFs written under it as constraints; multiplicities at the class ends, a filled diamond for a composition; generalizations as hollow arrows with their constraint; Notes.

Routes stored by a Tidy up are followed, as on the canvas. An MCD has no Legend. An MCD with nothing in it is not drawn.

It arrives in three places:

- **MCP**: `export_diagram` draws MCDs too, with a `notation` argument (`merise` or `uml`, Merise by default), ignored for System design diagrams, as `legend` is ignored for MCDs. Without a diagram it draws every Diagram of the Project. The server estimates the boxes' sizes from their text.
- **The app's SVG and PNG exports** of an MCD use this drawing instead of the page capture, in the Notation chosen in this browser for that MCD, with the sizes the canvas measured. The PNG is the SVG rasterized, as for System design.
- **The all-diagrams zip** holds the MCDs too, each in its Notation for this browser; nothing is left out any more.

## User Stories

1. As a developer, I want an agent to export my MCD as SVG over MCP, so that it can commit it to my repo and show it in the README.
2. As a developer, I want to choose the Notation of the exported MCD (Merise or UML), so that the README speaks the convention my readers know.
3. As a developer, I want Merise to be the default Notation over MCP, so that an agent that does not ask gets the app's default look.
4. As a developer, I want `export_diagram` without a diagram to return every Diagram of the Project, architecture and MCDs, so that one call illustrates a whole README.
5. As a developer, I want the exported MCD to look like my canvas (colors, Identifier underlined, Cardinalities where I see them), so that the README matches what I designed.
6. As a developer, I want the routes a Tidy up stored to be followed in the image, so that a tidied MCD stays tidy in the README.
7. As a developer, I want CIFs, Inheritances and Notes in the image, so that nothing I modelled is silently dropped.
8. As a developer, I want the image on white, so that it reads in GitHub's light and dark themes alike.
9. As a developer, I want plain shapes rather than embedded HTML, so that the image opens in GitHub, browsers, design tools and slides.
10. As a developer, I want the app's SVG export of an MCD to be that same image, so that a file I export by hand and one an agent exports agree.
11. As a developer, I want the app's PNG export of an MCD to be that image rasterized, so that both formats show the same drawing.
12. As a developer, I want the app's exports to use the Notation I am looking at, so that I export what I see.
13. As a developer, I want the all-diagrams zip to include my MCDs, so that one download holds every image of the Project.
14. As an agent, I want `notation` ignored on a System design diagram rather than refused, so that one call with `notation` set works on a mixed Project.
15. As an agent, I want the tool's note to say which Diagrams were drawn, so that I know which files to write.
16. As a developer, I want a binary Association in UML shown on its line between its two classes, so that the UML image reads as a class diagram.
17. As a developer, I want an N-ary Association in UML shown as a diamond with its CIFs as constraints under it, so that the UML image keeps what Merise shows with CIF circles.
18. As a developer, I want long names and many Attributes to fit their boxes, so that no text overflows in the image.
19. As a developer, I want names with characters such as `<` or `&` to come out intact, so that the SVG stays valid.

## Implementation Decisions

- **A pure drawing function for MCDs in the model package**, beside the System design one: `mcdSvg(nodes, edges, options)` returning an SVG string. Options: the Notation, the printed names (data type labels and the like, the app passing its UI strings and the server the English ones, as `SvgNames` does), the boxes' sizes (measured by the app, estimated by the model otherwise), a text measure, a margin. It shares the System design drawing's helpers: framing, escaping, routes and their stored points.
- **The UML derivation moves to the model package** as pure functions over Diagram nodes and edges and a size function: a binary Association's place on its line and its association class side, each Leg's peer Cardinality and composition, N-ary Associations, CIF constraints and generalizations. The Merise derivations (CIF links, Inheritance lines) move with them. The canvas layouts become thin adapters from React Flow nodes to these functions, so the screen and the image come from the same rules.
- **Labels the canvas places by geometry** (a Leg's Cardinality at the same point along its curve, twin Legs bent apart the same way) use the same shared geometry as the canvas.
- **MCP**: `export_diagram` gains an optional `notation` (`merise` | `uml`, default `merise`); its description and its note no longer mention MCDs as left out. Each image stays an `image/svg+xml` resource.
- **App**: the MCD canvas kind gets a `drawSvg`, like the System design kind, so the existing export path (SVG directly, PNG rasterized) applies; it reads the current Notation of the Diagram. The all-diagrams zip draws each Diagram with its kind's drawing; the "not in the zip yet" message goes.
- **No data schema change**: the Notation stays a per-browser preference, never stored in the Project.

## Testing Decisions

- Test external behavior: the SVG string a given Diagram produces, and what the MCP tool returns. Not the inner helpers.
- **`mcdSvg`**, in the model package, as `systemSvg` is tested: build an MCD through the Project document, draw it, check what the image holds — plain shapes and no `foreignObject`, escaped text, an Identifier underlined, Cardinalities, a CIF and an Inheritance in Merise; class lines with types, an association class, a diamond with its constraints, multiplicities and a generalization in UML; no Legend; a stored route followed.
- **The moved UML derivation**: its existing tests (notation, CIF, inheritance) move with it and keep passing.
- **MCP** (`server/src/mcp.test.ts`, prior art: the existing `export_diagram` tests): an MCD is drawn, `notation: 'uml'` changes the drawing, `notation` is ignored on a System design diagram, all Diagrams come back without a diagram argument.
- The app's exports and zip are checked by hand (e2e stays local).

## Out of Scope

- A PNG from `export_diagram` (a server-side rasterizer): its own backlog item.
- Storing the Notation in the Project.
- A Legend for MCDs.
- A dark-theme image.

## Further Notes

- On GitHub, a README shows a committed SVG with `![MCD](docs/mcd.svg)`; GitHub renders it as an image, with the reader's system fonts, which is why sizes are estimated generously.
